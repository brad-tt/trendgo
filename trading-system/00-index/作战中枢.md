# 作战中枢

## 一句话目标

把交易从“临场感觉”改造成“盘前有准备、盘中有纪律、盘后有数据、每周有迭代”的闭环系统。

## 当前入口

交易数据和日常记录进入 TrendGo：

- 应用入口：`../../app/`
- Skill 说明：`../../TOPTRADER_SKILL_USAGE.md`
- 当前规则索引：`rules-catalog-v1.md`

本目录保留规则和判断框架，不再作为交易数据录入入口。

## 当前最高优先级

1. 每笔真实交易必须进入 TrendGo 数据库。
2. 每笔交易前先过 `../05-setups/A-B-C级机会评分表.md` 和 `../05-setups/交易前检查清单.md`。
3. 任何风控硬规则触发，立刻执行 `../04-risk-control/硬规则.md`。
4. 盘后复盘必须落到一个可执行修正。
5. 每周只选择一个最值得优化的问题。

## 每日闭环

### 盘前

- 明确今天是否交易、主方向、关键位和禁做场景。
- 如需记录，优先通过 TrendGo Skill 或前端工作台。

### 盘中

- 下单前明确方向、入场价、止损、仓位和理由。
- C 级机会默认不做；B 级机会只小仓试错；A 级机会也必须先定止损。
- 出现报复交易、扛单、加大仓位翻本等信号时，优先停手。

### 盘后

- 补齐交易事实、纪律事件和复盘。
- 区分行情问题、形态问题、执行问题、情绪问题、风险问题。
- 只提炼一个明天要改的动作。

## 分工边界

### Joe 爸必须做

1. 最终决定是否下单。
2. 下单前给出方向、入场、止损、目标、仓位。
3. 到止损线必须执行。
4. 盘后提供真实结果，不能漏报亏损和违规。

### Codex 必须做

1. 把用户口述整理成结构化记录。
2. 缺字段时追问，不编造关键事实。
3. 判断是否触发规则或停手条件。
4. 盘后归因并沉淀下一步动作。
5. 维护文件结构，防止系统越写越散。

## 禁止事项

1. 没有记录，就不算复盘完成。
2. 没有止损，就不允许开仓。
3. 连亏后不允许用更大仓位翻本。
4. 当天触发硬熔断后，不再讨论新机会。
5. 不因为“今天感觉很准”临时放大风险。
