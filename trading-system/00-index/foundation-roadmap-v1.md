# 基础路线图 v1

## 定位

本文件是交易规则资料库的短路线图。应用运行和 Agent 写入不从这里进入，而是看根目录 `README.md`、`TOPTRADER_SKILL_USAGE.md` 和 `app/README.md`。

## 当前阶段

当前不追求复杂功能，只先把盘前、盘中、盘后、周复盘跑成稳定闭环。

## 当前产品边界

优先做：

- 盘前形成作战框架。
- 盘中记录每笔真实交易。
- 盘中触发硬规则时立刻停手。
- 盘后完成复盘和归因。
- 每周只选一个问题迭代。

暂不做：

- 自动交易。
- 复杂策略回测。
- 多用户体系。
- 大而全资讯聚合。
- 高级可视化大屏。
- 继续横向扩写大量新规则。

## 当前五个能力

| 能力 | 当前承接文件 | 成功标准 |
|---|---|---|
| 盘前准备 | TrendGo `盘前准备` 页面 | 开盘前有主方向、关键位、禁做场景 |
| 盘中记录 | TrendGo Skill / `盘中执行` 页面 | 每笔真实交易都有结构化记录 |
| 纪律风控 | `../04-risk-control/硬规则.md`、`rules-catalog-v1.md` | 触发硬规则后有停手记录 |
| 机会判断 | `../05-setups/A-B-C级机会评分表.md`、`../05-setups/交易前检查清单.md` | C 级不做，B 级小仓，A 级也先定止损 |
| 盘后复盘 | TrendGo `盘后复盘` 页面 / Skill `review` | 每日有归因，下一天有一个修正动作 |

## 当前建设判断

现有系统已经有足够结构。现在最大瓶颈不是缺文档，而是：

- 入口是否统一。
- 真实交易是否都进入数据。
- 风控是否真的执行。
- 复盘是否能转成下一周一个行为改进。

新增内容必须能直接提高执行、记录、风控、复盘或周迭代质量，否则先不加。

## 下一步

1. 保持目录收敛，不新增平行入口。
2. 用 `rules-catalog-v1.md` 稳定 Agent 规则引用。
3. 用 TrendGo `app/` 作为数据容器和展示工作台。
4. 等真实记录稳定后，再考虑失真日志、能力快照和进化看板。
