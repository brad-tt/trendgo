# TrendGo 使用说明

这份文档只描述当前版本应该怎么用，以及页面现在各自承担什么职责。

自然语言交易记录现在优先走 TrendGo Skill：Agent 解析字段后调用结构化提交接口。页面表单仍保留，用于查看、纠错和补录。

## 当前工作流

当前系统按 6 个一级页面组织：

1. `盘前准备`
2. `参考信息`
3. `盘中执行`
4. `盘后复盘`
5. `归档闭环`
6. `历史复查`

## 1. 盘前准备

目标：

- 确认今天是不是正确的交易日
- 看盘前决策面板
- 进入盘前作战台，补充今天的决策输入

当前页面结构：

- 上方是 `盘前决策面板`
- 中段是 `盘前作战台`
  - 已改成紧凑入口模式
  - 不再平铺第一步、第二步、第三步表单
  - 只保留 3 个步骤入口按钮
  - 点击后通过抽屉填写
- 下方是 `流程状态`
  - 只读
  - 只看全流程状态
  - 不在这里直接操作

盘前作战台当前 3 个步骤：

1. `今天做不做`
2. `关键提醒`
3. `专项计划`

## 2. 参考信息

目标：

- 放盘前会看的参考数据
- 不和盘前主决策区抢空间

当前承载内容：

- `恒指参考 / 日内振幅参考`
- 港股观察列表展示
- 美股观察列表展示
- 资讯接入预留位

注意：

- 观察池与高级项已经回到 `盘前准备`
- `参考信息` 当前以展示为主，不承担那块主编辑入口

## 3. 盘中执行

目标：

- 记录当天真实交易与纪律事件
- 判断当前还能不能继续执行

关注内容：

- 交易流水
- 纪律事件
- 当前盈亏
- 当前交易数
- 执行状态与风险信号

## 4. 盘后复盘

目标：

- 把盘中事实收口成复盘结论

关注内容：

- 复盘驾驶舱
- 盘后事实总览
- 结论上下文
- 复盘表单

## 5. 归档闭环

目标：

- 判断这一天能不能正式结束
- 检查验证字段、归档草稿、工作区产物是否对齐

这里有实际可操作的验证区：

- `盘前完成`
- `盘中记录完成`
- `盘后复盘完成`

也就是说，`盘前准备` 页面里的 `流程状态` 只是读这里的状态，不是在那里点。

## 6. 历史复查

目标：

- 只读回看历史
- 看统计、模式、重复问题与修正

默认不在这里修改历史数据。

## 当前页面取舍

当前版本有几个明确的 UI 取舍：

- `盘前准备` 顶部不再堆一大块不可点击的“盘前进度”
- 原“盘前进度”已改成页面后部的 `流程状态`
- `盘前作战台` 已折叠成步骤入口 + 抽屉填写
- 重复性的解释文案已经尽量移除，优先留空间给数据和入口

## 当前建议的使用顺序

1. 先进入 `盘前准备`
2. 看 `盘前决策面板`
3. 通过 `盘前作战台` 的 3 个步骤入口补充输入
4. 需要看参考时，再切去 `参考信息`
5. 盘中去 `盘中执行`
6. 收盘后去 `盘后复盘`
7. 最后在 `归档闭环` 做验证与归档
